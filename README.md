# Tiktok_Techjam2026_Blackroom

Optimized Transformer inference path, benchmarked against an explicit-PyTorch
reference implementation across the official shape suite.

The graded artefact is `OptimizedTransformerMixin` in `optimized_transformer.py`.
It is mixed in ahead of the baseline module tree:

```python
class UserOptimizedTransformer(OptimizedTransformerMixin, BaselineTransformer):
    """Baseline module tree, optimized forward."""
```

It overrides only `forward()`, adds no parameters and registers no buffers, so
`state_dict()` stays byte-identical to the baseline's and the harness's
`copy_model_weights(..., strict=True)` keeps working untouched.

Correctness contract, per output element:

```
abs(user - ref) <= 0.002   OR   abs(user - ref) <= 0.02 * abs(ref)
```

## Files

| file | role |
|---|---|
| `optimized_transformer.py` | the optimized forward. **This is the submission.** |
| `fused_kernels.py` | Triton residual+LayerNorm+cast kernel, cuBLASLt GELU epilogue |
| `torch_transformer_benchmark.py` | reference model, accuracy check, timing harness |
| `run_all_shapes.py` | sweeps the official shapes, writes `sweep_logs/` |
| `run_optimized_only.py` | runs one shape with no baseline, for shapes with no runnable reference |
| `measure_bound_ratio.py` | measures the fp16 error bound that justifies the precision policy |

`fused_kernels.py` is optional at runtime but **should be shipped alongside**
`optimized_transformer.py`. Its absence is handled (the import degrades to a
no-fusion stub rather than raising), but the fusions are worth a substantial
part of the speedup, so a copy without it runs correctly and slower.

## Running

```bash
python run_all_shapes.py                        # full sweep -> sweep_logs/
python run_optimized_only.py --inplace-output   # the shape with no runnable reference
```

`sweep_logs/` is gitignored: it is regenerated by the sweep and the timings only
mean anything next to the GPU and driver that produced them.

## Where the speed comes from

1. **Fused SDPA** — removes the `[B, H, S, S]` score tensor the baseline
   materializes twice. At the largest shape that tensor would be 20 TB, which
   is why the reference cannot run there at all.
2. **Causal triangle skip** — `is_causal=True` never computes the half of the
   score matrix the baseline computes and discards.
3. **Prefix-mask elision** — under causal attention with prefix padding the
   padding mask is provably a no-op, so it is dropped; SDPA reaches its fastest
   backends only with no `attn_mask` tensor.
4. **Fused QKV projection** — three `[d, d]` GEMMs collapse into one `[3d, d]`.
5. **Measured precision policy** — fp16 GEMMs with an fp32 residual stream,
   adopted per shape only when a measured error bound clears the tolerance.
   This is what unlocks SDPA's flash backend, which refuses fp32.
6. **CUDA graph capture** — for launch-bound shapes, decided by timing real
   replays rather than by a heuristic. Restricted to unsliced shapes.
7. **Slice-through-the-stack chunking** — large batches are cut into row slices
   that each traverse every layer before the next begins, so a slice stays
   L2-resident instead of being re-read from HBM at every layer boundary.
8. **Fused residual + LayerNorm + narrowing** — one Triton kernel instead of
   three passes, twice per layer. See `fused_kernels.add_norm_cast`.
9. **GEMM + GELU epilogue** — cuBLASLt's fused activation, using the exact erf
   GELU to match the baseline rather than the tanh approximation.

Every per-shape choice above is measured on the real shape rather than assumed,
and each is individually switchable for ablation — see the `TJ_*` toggles
documented at the top of `optimized_transformer.py`.

## Requirements

- PyTorch with CUDA
- Triton, for the fused LayerNorm kernel. Optional: without it that fusion is
  skipped and everything else still runs. Official Triton publishes no Windows
  wheel; on Windows use `pip install triton-windows==3.2.0.post21` (the 3.2.x
  series pairs with torch 2.6).
